# Extraction inventory for the 1.0.0 pipeline template (#55)

This is the function-by-function map from the nf-core pipeline template's generic
utility code to `nf-core-utils` exports. It answers one question per helper: does the
plugin already cover it, what changes at the call site when a pipeline switches, and
what stays in the pipeline. Gaps are listed in section 6. Items that wait on a
maintainer are marked **PROPOSED**. Maintainer decisions of 2026-11-16 are recorded
in section 6 and link the pull requests that carry them; the `UTILS_NFSCHEMA_PLUGIN`
wrapper question in section 5 is still undecided.

Plugin file:line references were checked against `main` at `f58032f`. Template and
modules references (`T:` and `M:`) come from the audit and were read from the pinned
snapshots below; they were not re-fetched when this document was written.

`completionEmail` known differences from the template:

1. A missing template file logs a warning and falls back to the body
   `Default email content` (`NfcoreNotificationUtils.groovy:292-293`). The audit called
   this a placeholder fallback (#118).
2. It sends through `Nextflow.sendMail` (`:367`), with a 30 second delivery timeout (`:396`).
3. It honours `plaintext_email`. T:307-309 builds an exception and never throws it.
4. It skips sending for Seqera Platform launches (`TOWER_WORKFLOW_ID`, `:350`) unless
   `params.force_completion_email` is true.
5. It writes the report files before sending (`:316-342`), and only when called.

## 8. Correction notes on the audit

The audit cited the line of the `@Function` annotation (for example `:176` for
`getWorkflowVersion`). This document cites the method signature one line below, so
every `NfUtilsExtension.groovy` line here is one higher than the audit's. The audit's
"PLACEHOLDER fallback" for the email template is the literal body `Default email content`.
All other plugin references checked matched.
