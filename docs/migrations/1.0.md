# Migrating to 1.0

This page is for pipelines that already load a 0.x release of nf-core-utils. Replacing the utility code copied from the nf-core pipeline template is a separate migration: see the [migration guides](index.md).

1.0 keeps every exported function name and default and renames nothing. A pipeline on 0.7.0 changes only the plugin version:

```groovy
plugins {
    id 'nf-core-utils@1.0.0'
}
```

**Runtime:** Nextflow 25.10.4 or newer, as for 0.7.0. CI tests the minimum and every supported stable release line (25.10, 26.04 and 26.10).

:::note{title="Not released yet"}
1.0.0 is not released. This page lists the changes merged so far; the [CHANGELOG](https://github.com/nf-core/nf-core-utils/blob/main/CHANGELOG.md) has the full entries.
:::

## New features

### Citation outputs

`citationOutputs(Map citations, List<String> formats = ['html'], Object mqcMethodsYaml = null)` returns citations as MultiQC HTML, BibTeX or CSL-JSON. Citation map entries now carry `info` (the raw `meta.yml` tool map) and `version`.

### Template helpers

Two helpers that the pipeline template defines locally are now exported:

- `genomeExistsError()` takes no arguments, reads `params` from the session and throws an `AbortOperationException` with the template's message when `params.genome` is not a key of `params.genomes`. A null genome or an empty `genomes` map passes.
- `logColours(boolean monochromeLogs = true)` returns the template's map of colour names to escape codes, all empty when `monochromeLogs` is true.

```nextflow
include { genomeExistsError; logColours } from 'plugin/nf-core-utils'
```

### Records from typed processes

`collectVersions()`, `generateVersionReport()`, `generateComprehensiveReport()`, `toolsFromVersionsTopic()`, `citationsOnTheFly()` and the deprecated `processVersionsFromTopic()` and `processMixedVersionSources()` read versions topic records from typed processes, `record(process, tool, version)`, as they read `[process, tool, version]` tuples.

## Enhancements

- `completionEmail()`, `completionSummary()` and `checkProfileProvided()` accept the text `true` or `false` (any case) for their flag arguments, as well as a Boolean, so `--monochrome_logs` and `--plaintext_email` work on the command line. Any other value logs a warning and uses the default. `generateYamlFromEvalSyntax()` accepts the same values for `includeWorkflow`.
- Remote files (`s3://` and other file systems) work as versions files, methods templates, email templates, IM templates and `meta.yml` files, given as a `Path` or a URI string.
- `collectVersions()` keeps a single versions `Path` instead of dropping it.
- `methodsDescriptionText()` no longer modifies the `meta` map you pass.
- A citation `doi` that is not a bare DOI is ignored with a warning instead of rendered.

## Breaking changes

None.

## Deprecations

Nothing new is deprecated. These four exports stay `@Deprecated`, delegate to `collectVersions()` and log a warning when a versions file is missing. They are removed in 2.0 (nf-core/nf-core-utils#123).

| Deprecated                     | Use instead         |
| ------------------------------ | ------------------- |
| `processMixedVersionSources()` | `collectVersions()` |
| `processVersionsFromTopic()`   | `collectVersions()` |
| `processVersionsFromFile()`    | `collectVersions()` |
| `softwareVersionsToYAML()`     | `collectVersions()` |

## Upgrading from releases before 0.7.0

Apply these in order, from the release you are on:

| Change                                                                                                                        | Since | What to do                                                                                                                    |
| ----------------------------------------------------------------------------------------------------------------------------- | ----- | ----------------------------------------------------------------------------------------------------------------------------- |
| `NfcorePipelineUtils` removed                                                                                                 | 0.6.0 | Use the exported functions.                                                                                                   |
| `getReferencesFile()` and `getReferencesValue()` removed                                                                      | 0.7.0 | Use `getReferencePath()`, `getReferenceMetadata()` or `getReferenceAttribute()`.                                              |
| Loading the plugin no longer validates startup                                                                                | 0.7.0 | Call `checkConfigProvided()` and `checkProfileProvided(args)` during initialisation.                                          |
| `completionEmail()` sends through Nextflow's `sendMail()`; `emailCommands()` and `runEmailCommand()` removed                  | 0.7.0 | Delete `assets/sendmail_template.txt`. Configure the `mail` scope (SMTP or SES) as for `nextflow run -N`.                     |
| Mail is skipped on Seqera Platform launches                                                                                   | 0.7.0 | Set the Boolean `params.force_completion_email = true` to keep nf-core mail on Platform, or use Platform's own notifications. |
| Nextflow floor is 25.10.4                                                                                                     | 0.7.0 | Upgrade the runtime.                                                                                                          |
| Citation metadata reads `publication.*`; flat `author`, `year`, `title` and `journal` still work when no `publication` is set | 0.7.0 | None required.                                                                                                                |
| `toolCitationText()` returns HTML, not plain text                                                                             | 0.7.0 | Write citation files as `.html`.                                                                                              |

## Pinning back

To return to 0.7.0, pin it in `nextflow.config`:

```groovy
plugins {
    id 'nf-core-utils@0.7.0'
}
```

Code that calls `genomeExistsError()`, `logColours()` or `citationOutputs()`, or passes flags as text, needs 1.0.
